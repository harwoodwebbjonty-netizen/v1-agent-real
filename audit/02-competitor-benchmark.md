Method: live web research (search + page fetch) conducted 2026-08-12, not drawn from training-data memory. Every factual claim about a competitor below carries its original source URL and access date. Where an official pricing/docs page returned an error or JS-only shell to the fetch tool (this happened for Salesforce, Apollo, and HubSpot's own pricing pages), the figure is explicitly marked as third-party-corroborated rather than primary-sourced. Where nothing could be verified via available tools, it is marked **unverified** rather than stated as fact.

This is not feature-counting. For each product: what it does, the user problem it solves, whether *this* CRM supports the equivalent, how completely, whether it's actually relevant to this product's target customer (small UK sales/broker teams doing cold-calling and Companies House-driven prospecting), and a recommendation — not "build this because a competitor has it."

## 2. This product vs. the field — the honest comparison

| Dimension | This product | Field pattern | Gap severity |
|---|---|---|---|
| Org/signup/invite | Admin hand-creates every account, no self-serve, no org concept at all | Every one of the 9 competitors has self-serve signup + email-based invites at minimum | **Critical for SaaS, irrelevant for continued single-team internal use** — see SaaS/Security doc §1-2 |
| Pipeline UX | Stage is a `<select>` dropdown, on a screen (`opportunityWorkspace.ts`) that's currently unreachable | All 9 competitors use kanban/drag-and-drop as a core, expected pattern | **High** — the single most visible "this doesn't feel like a real CRM" gap; also the cheapest to close relative to impact, since the data model (`opportunity_stage`) and even a full workspace UI already exist, just disconnected (see Visual/UX Audit 05-01) |
| Calling | Real, working `tel:` click-to-call + manual outcome logging; no provider integration | Close is calling-native (dialer built in); Pipedrive/Zoho/Apollo/monday all integrate a named telephony partner; Folk has none at all | **Medium-high** — this is the single feature category where this product's target user (cold-calling brokers) most resembles Close's exact use case, and Close is proof a small team will pay a premium for calling done well |
| Integrations marketplace | 8 total integrations, all hand-wired, no public API/webhooks/marketplace | Every competitor above 500+ integrations, several (Attio, Folk) ship API+webhooks on their cheapest paid tier | **High for a SaaS future, low for continued internal use** — building a marketplace is table-stakes only once selling to external customers; not needed to serve one team well |
| Automation | Fixed, developer-defined behaviors only (sequence scheduler, activity refresh); no user-configurable trigger→action builder at all | 6 of 9 competitors (HubSpot, Salesforce, Pipedrive, Attio, Close, Zoho) have a real workflow/automation canvas; monday has "Recipes"; Apollo/Folk lean on Sequences instead | **Medium** — genuinely absent, but the existing scheduler infrastructure (two-layer exception handling, retry logic) is a real foundation to generalise rather than a rebuild |
| Prospecting/enrichment | Companies House-driven discovery + AI enrichment — a real, working, differentiated engine | Only Apollo has an equivalent (275M-contact database) among the 9 | **This is a strength, not a gap** — validated by Apollo's own market position as proof this is a legitimate standalone value axis, not a nice-to-have |
| Command palette / keyboard-first interaction | Absent entirely | Linear teaches Cmd/Ctrl+K as primary navigation; Folk shipped pipeline-specific shortcuts as a named feature; Pipedrive/Airtable both have toggleable shortcut systems | **Medium** — cheap to add relative to impact for a "power user does the same handful of actions all day" persona (a cold-calling rep is closer to Linear's target user than to Notion's) |
| Ecosystem breadth generally | Deliberately narrow (8 integrations, one vertical use case) | HubSpot/Salesforce/Zoho all have 1,000+ integrations | **Not a gap for this product's actual customer** — Zoho's own decision to build Bigin, and repeated reviewer complaints about Salesforce/Zoho "clutter," both validate that breadth is not what a 5-20 person sales/broker team wants. Do not chase this number |

## 3. UX/interaction-pattern references (not CRMs)

- **Linear**: Cmd/Ctrl+K as the *primary*, taught navigation method, not a hidden power-user trick, with shortcut hints surfaced throughout the UI (Source: techinterview.org, accessed 2026-08-12). "The Linear Method" — strong opinions on core atomic objects, deliberately reduced visual noise in favor of *increased* hierarchy/density in navigation, pixel-level spatial alignment users feel without consciously noticing, constrained accent-color use for a "calm" look (Source: linear.app/now/how-we-redesigned-the-linear-ui, figma.com/blog, accessed 2026-08-12). **Directly relevant**: a cold-calling rep's dial→log→next-lead loop is a high-frequency repetitive action pattern, structurally closer to Linear's target user (an engineer triaging issues all day) than to Notion's (someone building a flexible doc).
- **Notion**: "/" slash command opens a searchable block-type menu inline, not a separate overlay (Source: thomasjfrank.com, accessed 2026-08-12); optimistic local-first editing (third-party technical teardown, not Notion's own engineering blog — flagged unverified in that specific detail). Trades density for exploratory flexibility — the opposite end of the spectrum from Linear.
- **Airtable**: Cmd/Ctrl+K for navigation, Ctrl+/ for the full shortcut list, no custom/remappable shortcuts (Source: support.airtable.com, accessed 2026-08-12). Borrows spreadsheet muscle memory directly (arrow-key navigation, Enter-to-edit) rather than inventing new idioms — directly applicable precedent for this product's own Leads table.

## 4. What to build vs. what to deliberately not chase

**Learn from**: Close's calling-first design (this product's closest real analog); Pipedrive's pipeline-as-home-screen simplicity; Attio's API/webhooks-on-every-tier posture as an AI-era default; Linear's keyboard-first density for a high-frequency-repetitive-task user; Folk's proof that a small team doesn't need Salesforce-grade schema rigor.

**Deliberately do not chase**: HubSpot/Salesforce/Zoho's raw integration-count and ecosystem breadth — not relevant to this product's actual customer, and Zoho's own Bigin spin-off is direct evidence that "the big CRM" and "the right-sized CRM for a small team" are different, both legitimate products. Do not add Salesforce/Zoho-style admin-configurable-everything flexibility — every one of those competitors' own reviewers cite that exact flexibility as the source of complaints from smaller teams.

**Gap that is genuinely absent and worth closing regardless of competitor pressure**: pipeline visualisation. Every single one of the 9 CRMs treats kanban/drag-and-drop as non-negotiable table stakes; this product doesn't have a working one at all today. This isn't "catch up with the market" advice for its own sake — it's the single most direct fix available, since the underlying stage data and even a full built workspace UI already exist (see Feature Gap Matrix and Visual/UX Audit) and simply need reconnecting plus a kanban rendering layer.
